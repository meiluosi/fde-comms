# 访谈回溯

拿作者自己做过的真实访谈回忆一遍，校准本 Skill 的提纲、纪要模板和规则是否贴合真实现场，并沉淀可匿名化的案例。做法参照 fde-demo 的回溯复盘。它**不是**对当时访谈质量的评分。

## 限制
- 全部来自回忆，按“转述”处理，不当作证据。有当时的书面材料（笔记、纪要、邮件、录音转写）时，它们比回忆强，在记录里写明文件名。
- 事后知道项目结局，必须单列，不能倒推当时的判断。
- 助手只记录回答，不补全没说过的内容；回忆里没有的写“未提供”。

## 偏差与对策
| 偏差 | 表现 | 对策 |
|---|---|---|
| 后见之明 | 知道结局后觉得当时的问法“显然” | 只写当时已有的信息，结局单列 |
| 幸存者偏差 | 只记得顺利的访谈 | 同时回溯一次不顺利的 |
| 记忆美化 | 对方的话被记得更配合 | 要原话和行为，没有就标“仅回忆” |
| 归因偏差 | 把拿到真话归功于某个问法，忽略当时的关系或场合 | 写出其他可能原因 |

## 做法
1. 选一次具体的访谈，先确认匿名化范围（不写客户名、人名、能反推身份的细节）。
2. 按 [production-forecast.md](production-forecast.md) 或同类案例文件逐节回答，答不上来的写“不记得”。
3. 填 [适配报告](fit-report-template.md)：这是主要产出。逐项对照本 Skill 的访谈提纲、纪要模板、五类问法、规则，记录哪些有用、多余、缺失、在真实现场行不通。
4. 把适配报告里的修订写回 DEVELOPMENT.md，并把匿名化后的片段加入 tests/behavioral-cases.md 作为回归用例。
