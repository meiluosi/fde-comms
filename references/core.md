# 沟通核心

## 沟通五问
每次起草或备课前先答（能从材料推出的不再问用户）：
1. 对方要做什么决定，或这次沟通后他该做什么？
2. 他的岗位职责和考核指标是什么？（决定他关心什么）
3. 他此前对类似项目的经历如何？（决定他的默认态度）
4. 他最担心什么？（失业、担责、麻烦、失去话语权，先诊断再套话术）
5. 什么证据能让他信？（他自己的数据、他认识的人、一次现场演示）

答不出就是未知，写“待确认”，不要凭想象补。

## 共用骨架
汇报、坏消息、请求支持本质是同一个结构：

**结论 → 数字（含口径、测量日期、置信度）→ 风险 → 明确请求（具体到人和时间）**

访谈反过来：先让对方说，最后才用复述句给出自己的结论，请对方否定。

## 通用纪律
- 不说“这个AI做不到”，说“这个做法的风险在……，建议的替代路径是……”。但必须带上代价和替代方案；确实不可行时直接写“不建议”，不用委婉掩盖，否则范围会无声膨胀。
- 对方的话不当事实：区分他说的、他做的、记录里有的。
- 每个故事都问频次：一个月几次、占多少。生动的异常不能直接变成设计目标。
- 中文职场语境：“挺好的”“有点绕”可能是婉拒；领导在场时人不会说真话；对方设计过的流程，背后曾有合理理由，不要评价流程“荒谬”。
- 动机是假设：猜到某人的考核动机，只用于调整方案，不在会上点破，也不写进会外可见的文件。

## 保密
- 访谈记录默认敏感。纪要只给受访者本人；跨人汇总去掉姓名、岗位和能反推身份的细节。
- 不把受访者对上级、同事的评价写进任何对方上级可能读到的文件。
- 对外或写书前，生成匿名化副本。
