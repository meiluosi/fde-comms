# 访谈模式

## 先分清这场会议的目的
三种目的节奏不同，塞进同一场会通常三样都没做好：

| 目的 | 节奏 | 你的角色 | 产出 |
|---|---|---|---|
| 建立信任 | 放松、闲聊 | 少说多听，问工作日常，少提项目 | 人物关系与态度的观察（不直接问） |
| 收集需求 | 有结构、覆盖全 | 控场，结构化提问 + 现场观察 | 流程与痛点，带频次 |
| 验证假设 | 具体、追问 | 带草稿去被否定 | 被确认或被推翻的理解 |

信任是整个过程中持续要观察的状态，不是只在第一轮完成的阶段。

**只有一次会怎么办**（现实中很常见）：约 10% 时间开场与建立安全感，70% 流程还原与异常，20% 复述与确认。不要在同一个问题里同时收集和验证。

“拿草稿去被否定”：草稿须写成能被推翻的具体命题（“我理解这一步是 A 在做，平均 20 分钟，对吗？”），否定与修正都记下“为什么”。行业图和问题定义都可用这种方式，ramp 的第 4 步就是这个动作。

## 会前
1. 对方岗位职责与考核；这家企业上一个信息化项目的结果。
2. 问题清单，同时准备好随时放弃它。
3. 谁不该在场：直属上级在场时，员工不会说流程有多糟。能分开就分开。
4. 能让对方打开的实物：昨天那张工单、那份表、那个系统界面。实物是回忆的锚点。
5. 不要预设对方的需求是错的；客户指定的产品是约束，先记录。

## 会中
开场不说“想了解贵司在AI方面的需求”，改成“请您带我走一遍昨天实际处理的那一单，中间觉得麻烦的地方停下来说说”。让人回忆具体一件事，比让他总结更接近真实，但回忆仍会美化自己、偏向近期，所以要用实物和日志交叉核对。

手写或经同意后录音，尽量不边听边敲键盘。

### 高命中的五类问题
| 类型 | 例 | 注意 |
|---|---|---|
| 流程还原 | “带我走一遍昨天那一单，从收到通知开始” | 要具体某一次，不要“一般怎么做” |
| 异常挖掘 | “上一次出岔子是什么时候？最麻烦的一单什么样？” | 必追问频次，防止把长尾当主体 |
| 时间去向 | “哪一步最花时间？砍掉一个环节砍哪个？为什么这步花时间？” | 答案常与你的猜测不同 |
| 反事实 | “系统明天没了怎么办？有它之前怎么做？” | 对方说得出替代做法，不等于不重要，还要问替代的代价 |
| 权力地图 | “最后谁拍板？要改流程谁点头？做成了对谁最有好处，谁可能不高兴？” | 最后一问价值最高也最露骨，建立信任之后再问，不在第一次问；首轮靠观察 |

### 基本不出东西的五类问题
诱导式（“您是不是觉得效率很低？”）；术语式（“对RAG有什么期待？”）；二选一（过早收窄）；空泛式（“您有什么痛点？”）；冒犯式（“为什么设计得这么复杂？”）。

### 需求真实性信号
有人为它花过钱（尤其自己的钱）；为它反复加班；亲手搭过东西。信号越贵越可信。反向信号：谁在回避这个话题。

### 固定问题：自己做的东西
“您平时有没有自己整理什么东西帮自己记这些？”“有没有哪张表是您自己做的、系统里没有的？”拿到后读三层：
1. 内容：有哪些字段，说明什么信息关键；
2. 结构：为什么这样排列，反映使用者的思维路径；
3. 缺失：为什么系统没满足，是没做还是做了不好用（后者更值得追问）。

## 会后（24 小时内）
1. 整理纪要发给受访者确认，必须有“我理解您说的是……对吗”的复述句。用 [纪要模板](../templates/interview-notes.md)。
2. 区分：对方说的 / 实物或日志里有的 / 我的推断。
3. 记下新疑问，作为下一轮的种子。
4. 需要时按 [handoff.md](handoff.md) 转成证据条目。

## 审稿检查（审提纲或纪要时）
- 是否把三种目的塞进一场；开场是否要对方总结。
- 问题里是否有五类无效问法；是否所有故事都有频次追问。
- 纪要是否有复述句、是否区分说法与实物、有无泄露个人评价。
- 数字是否有来源与口径。
