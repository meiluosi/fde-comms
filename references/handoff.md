# 与其他 FDE Skill 的衔接

| 事项 | 归谁 | 本 Skill 做什么 |
|---|---|---|
| 判断问题是否真实、该不该上 AI、根因与干预 | fde-problem-framing | 提供访谈证据，不下结论 |
| 原话→期望变化→候选问题（说的/想的/需要的） | fde-problem-framing 的需求澄清 | 只设计怎么问出来；“想的”和“需要的”是推断，标假设 |
| 需求真实性信号（花钱/加班/亲手搭）与自制资产三层读法 | fde-problem-framing `references/evidence.md` | 访谈里主动问这些信号，结果交给 framing 判断；本 Skill 不另存定义 |
| 问题陈述（现状/目标/约束/验收） | fde-problem-framing 的定义卡 | 不另起模板；翻译给总部的需求单属于后续版本 |
| 行业图、业务域、活动表、四个数字 | fde-ramp | 访谈时把四个数字（耗时、日频次、出错率、单次代价）问出来；“拿图去被改”按“验证假设”访谈做 |

## 访谈 → 证据条目
每条记录沿用 problem-framing 的证据协议字段：ID、命题、状态（事实/假设/推断/冲突）、来源（访谈对象的岗位，不写姓名）与日期、原话、单位/分母/时间窗、限制、后续动作。
- “受访者说平均 20 分钟”：来源事实是“他这样说”；是否实测仍待验证。
- 两个人说法冲突：标冲突，不平均，先核对流程边界和时间窗。
- 一线抱怨经匿名化后再进入汇总。
